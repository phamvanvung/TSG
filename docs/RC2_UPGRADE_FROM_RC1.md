# Upgrade an existing rc1 author-machine checkout to rc2

The rc2 overlay is designed to preserve the expensive `results/` already produced by the rc1 checkpoint execution. It does not contain `configs/paths.json` and does not contain generated results.

From the existing rc1 repository root, unpack the overlay with overwrite enabled. Keep your current machine-specific `configs/paths.json` in place.

Then execute only the newly required release steps.

## 1. Stage bundle-safe project-authored reference artifacts

```bash
python scripts/stage_public_reference_artifacts.py \
  --config configs/paths.json
```

The staging tool SHA-verifies the frozen project artifacts and refuses to stage text files containing private author-machine paths. BDD100K data and detector checkpoints are never copied.

## 2. Run the newly migrated RT-DETR detector-performance stage

```bash
python scripts/rtdetr/run_rtdetr_reproduction.py \
  --config configs/paths.json \
  --from-stage evaluation \
  --through evaluation
```

This reproduces the paper's RT-DETR Gaussian VAL NONE vs CLEAN-KD result and paired source bootstrap.

## 3. Check same-run Step-12 -> Step-14 linkage

The rc2 verifier requires Step 14 to cite the SHA-256 of the Step-12 cell table generated by the public chain. If the existing rc1 Step-14 run used a byte-identical historical Step-12 table, no expensive rerun is needed.

Run the final verifier after environment capture. If it reports a Step-12/Step-14 linkage mismatch, rerun only:

```bash
python scripts/rtdetr/run_rtdetr_reproduction.py \
  --config configs/paths.json \
  --from-stage finite-horizon \
  --through orientation
```

The rc2 finite-horizon runner preferentially consumes the local public Step-12 table.

## 4. Capture and freeze the successful environment

```bash
python scripts/verify_environment.py \
  --require-cuda \
  --output results/environment_successful_run.json

python scripts/freeze_environment_from_report.py \
  --report results/environment_successful_run.json \
  --write

python scripts/verify_environment.py \
  --require-cuda \
  --output results/environment_successful_run.json
```

The second report must have `status: PASS` and `contract_complete: true`.

## 5. Final numerical closure

```bash
python scripts/verify_end_to_end.py \
  --results-root results \
  --environment-report results/environment_successful_run.json
```

Stable release requires:

```text
FULL_CHECKPOINT_REPRODUCTION_PASS
```

## 6. Final public packaging

Before publishing stable v1.0:

- choose and add the repository `LICENSE` deliberately;
- do not include `configs/paths.json`;
- do not include BDD100K data or detector checkpoints;
- run `make check` and `make manifest`;
- rescan the final release tree/archive for private paths;
- record the final archive SHA-256 and, when available, paper DOI/identifier.
