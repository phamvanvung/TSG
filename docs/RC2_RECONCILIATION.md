# rc1 → rc2 scientific reconciliation

## Why rc2 exists

The first full author-machine execution of `v1.0.0-rc1-end-to-end` completed both checkpoint chains. That execution exposed two implementation hotfixes on the YOLO path and, more importantly, showed that the rc1 **reference-target JSON** contained stale RT-DETR values that predated the corrected authoritative Step-14 numerical-replay protocol.

rc2 changes the release bookkeeping and public execution graph; it does **not** introduce a new scientific method or tune a result.

## 1. RT-DETR Step-14 target reconciliation

The corrected authoritative Step-14 protocol uses:

- the Step-12-frozen `u_C` as the primary horizon predictor;
- recomputed `u_C/u_rel` only as replay diagnostics;
- exact interventions at alpha `0.25` and `4.0`;
- central recomputation of the final per-view correlations from frozen `u_C` plus the exact Step-14 intervention outcomes;
- source-balanced aggregation and 5,000 source bootstraps with seed 2027.

The successful public checkpoint run produced:

```text
rho_small = 0.5429078235502545
rho_large = 0.16597366522366522
Delta_rho = 0.3769341583265893
95% CI    = [0.316999866536965, 0.4379358642467023]
```

These values are therefore the rc2 successful-reference targets. The older rc1 target values are retained only under `reference_results/legacy_v1.0_rc1_stale_targets.json` for audit history and are not release gates.

The same successful run froze the public checkpoint implementation outputs:

R_ST SHA256 = 6c1e44b533db580284a32b4933713edd407521bacbd334d2716bf4a35b00128b

Their fit populations and scientific firewalls were unchanged: 120 source identities, 360 Gaussian views, 576,000 P4 cells per coordinate map, and 5,769 normalized task-gradient vectors for `C_g`.

## 3. YOLO authoritative-vs-rebuild distinction

The YOLO teacher-canonical maps and `C_g` used by the confirmatory Exp15A/Exp16A analyses remain the previously frozen authoritative artifacts:

```text
R_NT = 2caa1712e6493ca25f5ceb30dfe4d831eb4485e76c51bbf5372571fc0e0e330f
R_ST = cebc13623188e0ee6b83410f318a53798bfc8264b52f55237b4558bd76b55cd8
C_g  = e765f903ca3308bb090b6e0985fd14ba7c46151da2cf2c4d7b339faa34a9f64d
```

A freshly regenerated YOLO `C_g` on the successful execution machine is retained as a **rebuild audit artifact**, not silently substituted into the frozen confirmatory analysis. The verifier checks the confirmatory provenance hashes rather than incorrectly demanding that the rebuild-audit file equal the frozen confirmatory `C_g` byte-for-byte.

## 4. Public-chain linkage correction

rc1 allowed Step 14 to read an external historical Step-12 cell table through configuration. rc2 prefers the Step-12 table generated by the same public run whenever it exists. The end-to-end verifier also checks that the Step-14 provenance hash equals the local public Step-12 table hash.

This makes the public chain genuinely end-to-end rather than a sequence of individually reproducible stages joined by a private intermediate.

## 5. Detector-performance coverage

rc2 adds a first-class RT-DETR Gaussian VAL evaluation stage. It reproduces the paper's detector-level result before the mechanism chain:

```text
RTDETR-NONE macro      = 0.234487996
RTDETR-CLEAN-KD macro  = 0.250636082
Delta                  = +0.016148086
paired 95% CI          = [-0.004753495, +0.038906672]
```

The paired bootstrap is over the 250 VAL source identities, 5,000 valid replicates, seed 2027, with the fixed CORE9 class set. Resampled draws missing a CORE9 target class are rejected and resampled rather than changing the endpoint.

## 6. YOLO implementation fixes folded into source

Two rc1 runtime hotfixes are now normal rc2 source code:

1. temporary Ultralytics validation YAMLs contain both `train:` and `val:` because Ultralytics 8.4.131 validates both keys even under `model.val()`;
2. native YOLO prediction tensors are cloned before NMS so Ultralytics' in-place box conversion does not mutate a PyTorch inference tensor after leaving `torch.inference_mode()`.

Neither change alters a scientific metric or dataset.
